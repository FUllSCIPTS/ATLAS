# Testing and release evidence (1.6.0)

ATLAS Go 1.6.0 is a Python/Kivy app with on-phone accounts, a live map, simulated rides and deliveries, pre-booked rides, SOS, sandbox bank payments and an optional PostgreSQL server. Tests exercise local accounts, bookings, ordering, seller and driver workflows, payments and payouts, live progress and every bundled model, and the server on a real PostgreSQL. They do not contact live drivers, restaurants, banks, payment providers or ML services; the map-tile path is tested against a local stand-in tile server, and the server tests use a local database.

## Bugs fixed during this handover

1.6.0 (found while writing the new tests, before release):
- A failed dispatch of a pre-booked ride restored the earlier state and then reused that same snapshot as its rollback point, so a write failure during the second save could have left the booking marked *scheduled* with its seats already released. The failure path now takes a fresh snapshot.
- The *Pay with* card on a pre-booking said the bank is asked "when you book"; it is asked when the driver is sent, and the card now says so.

1.5.0 (found by the new tests before release):
- A NUL byte in the sign-in email reached PostgreSQL and produced a 500; an email that is not shaped like one is now refused without touching the database, and unsupported characters elsewhere return 422.
- `Retry-After` on a locked sign-in said 61 seconds for a 60-second lock.
- A saved file whose payment amount differed from its booking's fare was accepted, because the ledger still balanced; the booking and payment amounts are now compared.

1.3.0:
- On phones the ride map was fitted before layout (at Kivy's default 100 × 100) and showed the whole county; it now refits once the real size is known, until the user pans or zooms.
- Shared seats stayed reserved after a completed shared ride; they are now released on arrival as well as on cancel.
- The acceptance run used the real clock, so prices and surge features could change with the time of day; it now pins an ordinary hour and a busy hour.

1.2.0:
- A ride-request decline without a fallback driver counted as an offer before failing; validation now happens first.
- The app's driver-picking method was named `dispatch`, which shadowed Kivy's event dispatcher and crashed start-up; renamed `pick_driver`.
- Courier timing for kitchens slower than the trained range kept the courier waiting at the counter; the table's edge margin is now extrapolated.
- Registration tabs and map buttons no longer break words on narrow screens with large text.

1.1.0 and earlier:

- Desktop startup no longer depends on a pre-existing configuration directory.
- Preview geometry is configured before the graphics surface is created, preventing clipped/black upper screen regions.
- Android uses system screenshots with an acknowledgement handshake; in-app OpenGL readback had produced black capture regions on the emulator.
- Screenshot filenames are normalized, so documentation links point to the real captures.
- Invalid saved booking stages and out-of-range form values recover without crashing the UI.
- Booking, shared-seat, basket and checkout changes roll back in memory if persistence fails.
- Reset removes the quarantined invalid-state file as well as current demo history.
- Android system-bar spacing prevents status and gesture controls from overlapping the app header and navigation.
- Bottom navigation remains readable on a narrow screen with increased text size.
- Android packaging installs the libtool/libltdl development dependencies needed by the Python runtime.
- CI screenshots, results and sample data are excluded from the packaged application.

## Reproduce

```bash
pip install -r requirements-dev.txt
python -m pytest tests
ATLAS_UI_TEST=1 ATLAS_DATA_DIR="$PWD/local-data" python main.py
python scripts/verify-acceptance.py local-data/test-output
```

For a second desktop configuration, set `ATLAS_PREVIEW_SIZE=360x780` and `KIVY_METRICS_FONTSCALE=1.2`, using a fresh data/output directory. The GitHub workflow defines the Linux/Android build environment and runs the full checks. Keep acceptance directories outside release source or excluded in `buildozer.spec`.

See [release validation](../releases/VALIDATION.md) for the exact source revision, successful run, binary checksums and artifact URLs.

## Remaining release work

For 1.6.0 the unit tests and both desktop configurations were executed for this change (17 November 2026); the server and `backend.py` are unchanged, so the server tests were re-run and the connected-mode run was not. The Android build and the Android 16 emulator run are done by GitHub Actions on push; their result is in [release validation](../releases/VALIDATION.md). Not tested: the `tel:` and `sms:` hand-off on a physical phone (the emulator run checks the link the app hands over, not the dialler or messaging app), and a pre-booking whose pickup time passes while Android has the app in the background.

For 1.5.0 the unit tests, both desktop configurations, the server tests and the connected-mode run were executed for this change; the Android build and the Android 16 emulator run then passed in GitHub Actions ([run](https://github.com/FUllSCIPTS/ATLAS/actions/runs/43961614528)): 418 assertions, 32 screenshots, release AAB validated (see the [release validation](../releases/VALIDATION.md)). The Docker image and Compose file for the server were not run. A real bank or payment provider, TLS in front of the server and a phone on a different machine from the server have not been tested. Real GPS fixes and the location permission dialog, real OpenStreetMap tile downloads on a phone, physical Android phone/tablet testing, TalkBack and switch-access review, large font settings beyond the tested configuration, battery/performance profiling, Play pre-launch reports, developer identity/listing declarations and any account-specific testing requirements remain owner checks. The model does not provide production transport or food services. Google Play review is a separate process; passing these tests does not guarantee acceptance.
